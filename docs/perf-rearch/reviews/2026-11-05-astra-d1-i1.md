# Astra review: D1-I1 (00b333163), 2026-11-05

**Verdict: ACCEPT WITH FIXES, as a foundation for I2.** The shipped default
stays exact; the branch is not merged until validation passes.
Reproductions are in `~/.cache/perf-rearch/scratch/astra-d1-*`.

1. **Blocker: a partial commit changes the exact rerun's inputs.**
   - Repro: 160 files, d.ts emit, `include **/*.ts`, `exclude []`, and a
     directory occupying an output name. Exact exits 2 with TS5033. The
     speculative run writes some d.ts files, then execs; the rerun sees them
     as inputs (TS5055) and exits 1.
   - Fix: no live-filesystem replay after a partial commit. Either keep the
     input snapshot, or handle commit failures through the normal emit error
     path without restarting.
2. **Blocker: committing files first breaks the observable order.**
   - Repro: `traceResolution` with stdout redirected to `out/f0.js`.
   - Fix: keep stream and file operations in one ordered log and handle
     aliased sinks. Routing `traceResolution` runs exactly is the immediate
     conservative step.
3. **Blocker: only the main config is checked for being re-readable.**
   - Repro: an `@/dev/stdin` response file, then a commit failure; the rerun
     has lost its arguments.
   - Fix: track replayability for response files, extended configs and
     inputs. Either run non-replayable invocations exactly, or keep their
     bytes.
4. **High: the end bound races worker publication** (`program.rs:4634`,
   `4923`). Publish before signalling completion, or add an acknowledged
   barrier, and test it with a stalled publication.
5. **High: T5b misses a merge into the last stored diagnostic outside a file
   check** (`checker/certificate.rs:147`). `add` must report whether it
   inserted or reused an entry, with explicit epochs. Test reuse of the
   first and last entries and a one-entry collection.
6. **Medium: the pid marker is user-controllable.**
   `export GOPORT_PROTOCOL_EXACT_RERUN=$$; exec tsgo` turns speculation off.
   Fix: a consumed internal handoff, such as a validated inherited fd.
7. **High: the default exceeds the validated scope.** It stays experimental
   until cycle agreement, the relation bound and the campaign are done.
8. **High for validation: the identity tools ignore diagnostic order**
   (`d0_partition.py:286`, `d1i1/identity.py:223` use multisets).
   - Fix: require exact ordered output, use multisets only to explain a
     failure, and check determinism before any referee.
   - The saved 66 results were checked by hash and are fine.

**Also:**
- **Virtual count:** the statement-only reset fixes explicit type arguments,
  and there is no counterexample to the structural argument (it is still
  conditional on A1).
- **Memo-scoped resets** for t3-server are not yet a demonstrated solution.
  They need a precise compositional rule.
- **Signal handling** across exec is under-tested.
- **The report's counts:** the saved data has 27 fired runs, not 23, and 21
  SilentLimit runs, not 19. Splitting can start at 33 checked files, not 128.
  Regenerate the report from an immutable manifest.

**Policy recommendation:** keep every class falling back for now.
- **CountBound** is the first candidate for relaxing, after the bound is
  repaired and real near-limit runs are separated from conservative
  overestimates.
- **SilentLimit, ReportedLimit and Collection:** evaluate each trigger on its
  own.
- Dropping a fallback is an empirical compiler change. It needs frozen
  holdouts, adversarial coverage and a rollback criterion. Never justify it
  by suppressing diagnostics or whitelisting projects.
