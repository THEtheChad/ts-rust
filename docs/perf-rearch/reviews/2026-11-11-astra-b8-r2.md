1. **A nested API build can deadlock** (`host_queries.rs:170-174`, `ipc/conn_async.rs:750`,
   `program.rs:4438`, `api/session_p1.rs:3220`).
   - **Sequence:** orchestrators A and B, both single-threaded. A's checker probes through a
     callback, and the loading thread waits for the client in `question`. The client sends B's
     `build` and then A's callback answer. B is dispatched inline inside A's wait and reaches the
     symbol-id carry from A's running checker. Now B waits for A's checker, and A's checker waits
     for `reply.send`, which needs B to return.
   - Go serializes builds with `buildMu` (`api/session.go:1891`) and keeps handling responses
     (`ipc/conn_async.go:96-108`).
   - **Fix:** defer nested build-family requests behind the active build, with no blocking mutex on
     the loading thread, while still dispatching callback responses. Add the two-orchestrator
     interleaving as a regression case.
2. **The timestamp scenario returns `missing`, not its configured time**
   (`parity_api_session.py:352-357`, the sandbox mount at `:598`). `Callbacks` runs in the parent,
   while the outputs live in the server's private mount namespace, so `os.lstat` fails. The item
   proves only that a `stat` request was made, not that timestamp A was restored. Fix: get the
   metadata from inside the sandbox, or script it with no parent FS access; assert both the
   returned timestamp and the final `.d.ts` mtime.
