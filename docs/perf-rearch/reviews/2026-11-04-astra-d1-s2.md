# Astra review: D1-S2 certification design (2ed12a6bc), 2026-11-04

**Verdict: PROCEED WITH CHANGES.** The gain justifies building and testing a
revised design, but it is not ready to become the default.

1. **Blocker: the virtual instantiation count still resets on cache-dependent
   paths.**
   - The counter resets at every `checkSourceElement`, nested ones included.
     Example: `resolveCall`, then `checkSourceElements(typeArguments)` on a
     cold `getResolvedSignature` miss. The warm hit skips that path
     (`checker_p03.rs:321`, `checker_p10.rs:761`).
   - Fix: enclosing counters that survive nested resets, or resets only at
     boundaries shared by both runs. Add a generated repro that crosses the
     threshold.
2. **Major: the "monotone" limits are conditional on equivalent demand paths
   and cache results (A1).**
   - An id-order change can make the cold checker return `Maybe` early.
   - The relation-budget bound needs validating over all relation kinds,
     entry points and phases, with conservative arithmetic near 16M.
   - Keep the direct overflow triggers. The relation bound and cycle
     agreement fall back at end of pass, which costs more than a first-fire
     fallback.
3. **Blocker: cycle agreement keys are too coarse.**
   - Declaration position plus property merges instantiations.
   - Printed fingerprints are weaker than semantic equality, and printing
     itself resolves state.
   - `pushTypeResolution` marks every participating stack entry.
   - Fix: instantiation-aware identities; record every affected outcome and
     its diagnostic effects; cover default and awaited cycles; compare
     without new checker work.
   - Agreement with c4 still needs the earliest-demander argument, or a
     direct comparison against c4.
4. **Major: id behavior is acceptable as empirical equivalence.**
   - Spacing is not allocation order. Resolving sentinels, deferred queues
     and once-only guards also need coverage.
   - Perturb every dynamic identity: symbol ids, union keys, late-bound-name
     digit boundaries, and the replayed serialized-type `added_length`.
   - **Any unexplained divergence blocks the flip, id-order ones included.**
5. **Major: diagnostics lifecycle.**
   - T5b′ is mandatory.
   - Fileless, declaration-emit and global/deferred phases need collection
     epochs: directive filtering, `skippedOnNoEmit`, related-info order.
   - Monitor through emit completion.
   - **Separate parity fix:** Go shares diagnostic pointers, while tsc-rs
     clones values (`ast/misc.rs:963`), so a later mutation is visible only
     in Go.
6. **Blocker: the fallback needs transactional writes.**
   - Hold every generated file, map, build info and mkdir until all
     certificate phases finish. The current early-emit sink
     (`program_emit.rs:620`) opens too early.
   - On fallback, discard the held writes and stop the workers.
   - The exact run gets the same inputs, args, cwd and env, and must never
     select refinement again.
   - Preserve stream identity, ordering and exit status.
   - Run `--incremental`, `--extendedDiagnostics`/counts, tracing, watch,
     `-b`, LSP and API exactly, chosen before speculation; or validate
     incremental separately.
7. **Major: the matrix evidence predates the certificate.**
   - Its reference is Rust c4, not Go, and its binary predates the virtual
     count.
   - Rerun the campaign on the finished implementation, with direct
     pinned-Go comparisons reported separately, and report which mechanisms
     were exercised.
8. **Moderate: measure the finished implementation end to end**, including
   late fallback and buffering costs.
   - Go-N equivalence earns no credit; only c4 counts.
   - A predictor may route likely losers to c4, but predicted-safe runs must
     still be monitored.
   - Start with static refinement plus whole-process fallback. No per-group
     replay or stealing yet.

**Validation additions:**
- nested-reset paths below, at and above each threshold;
- relation bounds against c4;
- multiple instantiations per cycle declaration, and silent cycles;
- verified multi-file producer/consumer splits;
- id-tie, once-only and deferred-order generators, with order reversed
  within one file;
- fallback injection during global diagnostics, d.ts emit and build info,
  from clean and pre-populated out dirs, including write failures;
- stream, redirection and exit-code tests;
- weakening mutants;
- frozen holdouts and seeds, compared against pinned Go c4.

Passing means coverage plus zero divergences, not hours spent.
