# C2: the loader's env switches (2026-11-06)

Lane C2 of the perf/first-principles cleanup (brief: "Code quality: no old
paths"), after L1. Base `427ff93d5`. Each switch: what ships (env unset), its
class, what went, and the evidence. Classes as in C1: **(a)** old/fallback or
A/B path: deleted; **(b)** product option or tuning knob: kept; **(c)**
needed by a proof tool or test: kept behind the `diagnostics` cargo feature.

## Which path matches Go

Both sides of every switch match Go where the gate looks:

- **Default (shipped) path:** the base's own full run (`base-current`) has no
  loader item that is not good; its only DIFFs are fuzz crashes and timeouts
  that Go shares.
- **Non-default path:** the base release bin with all nine switches on their
  other side (`bins/tsgo-c2base-alloff`, a wrapper), parity full on the cli
  and lsp tiers: cli 170 MATCH, lsp 2,631 MATCH and 27 GO-BROKEN, 0 lost
  (`~/.cache/perf-rearch/c2/parity-alloff`). The lsp tier covers first and
  keyed loads, watch sessions (registrations, file events, first loads) and
  `GOPORT_PARSE_THREADS=1`; the cli tier covers `--noEmit`, emit, `-b`,
  incremental and listFiles.

So each switch keeps its default, which is also the faster path (below).

## Diagnostics behind the feature

- **`GOPORT_LOAD_DUMP`:** the module (`compiler/load_dump.rs`) and every call
  site (`files_parser`, `file_loader::collect`, the project hosts' acquire
  notes, `dump_program_load`, `dump_snapshot_fs`, `PackageJsonInfoCache::dump_lines`,
  `CachedFs::dump`) are `#[cfg(feature = "diagnostics")]`, as L1's `diag`
  modules are. The acquire notes no longer touch a thread-local per acquire.
- **`GOPORT_LOAD_TIMES`:** `LoadTimes` is a zero-sized no-op without the
  feature (`start() -> Self`, as C1's emit timers), so the call sites are
  plain `times.mark(..)` calls.
- **Resolve ahead:** the `GOPORT_RESOLVE_AHEAD_STATS` log, the per-load counts
  (`LoadStats`, `last_stats`, `previous_keys`), `AheadLink::missing`, and the
  test hooks (`set_mode`, `set_first_load`, `set_after_workers`,
  `hold_workers`, `inject_worker_panic`, `wait_for_frees`, `wait_left`,
  `wait_idle`) are diagnostics-only. The resolve-ahead go_baselines tests
  build only with the feature, as the parity tests tier builds them; CI's
  go_baselines step now passes `--features diagnostics`.
- **Duplication:** `load_dump::sorted_lines` is now a re-export of
  `vfs::cachedvfs::sorted_lines` (diagnostics-only).

## Tool fix

`quality.py` took a cfg'd struct field (which ends at a `,`) as running to
the next `{` or `;`. A `#[cfg(all(test, ...))]` field then hid the shipped
`GOPORT_RESOLVE_AHEAD_THREADS` read. A `}` before either now ends the item
(snapshot version 12).
