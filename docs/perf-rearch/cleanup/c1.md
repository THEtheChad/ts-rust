## Diagnostics feature

New cargo feature `diagnostics` (ts_goport → goport_core, off by default).
Env names only read in a diagnostics build: `GOPORT_VERIFY_REUSE`,
`_LOG`, `_DIR`, `_CHILD`, `_CHILD_ARGS`, `_CHILD_OUT`, `GOPORT_REUSE_STATS`,
`GOPORT_CHECKER_CALL_LOG`, `GOPORT_EMIT_PHASE_TIMES`,
`GOPORT_DTS_TWIN_CHECK`, `GOPORT_FLOWSKIP` (`verify`),
`GOPORT_LIB_SNAPSHOT`/`GOPORT_LIB_PARSE_SNAPSHOT` (`trace`).

- `project::reuse_verify` is compiled only with the feature; the hooks in
  `Project::create_program` moved into `reuse_verify::after_update`.
  `program::reuse_verify::dump` stays in every build (tests use it).
- `phase_times::enabled` and `checker_call_log_enabled` are `false`
  constants without the feature (no atomic load on the shipped path).
- `tests/plain_early_emit.rs` has `required-features = ["diagnostics"]`;
  the verify-mode go_baselines tests are `cfg(feature = "diagnostics")`.
- `parity_tests.py` builds the test binaries with
  `--features ts_goport/diagnostics`, so the gate still runs them.
- Tools that need a diagnostics build: `b1_emit_parity.py`, `b1_time.py`,
  `d1/run-calllog.sh`, `a1/stress.mjs`, `a1/verify-typing.mjs`.

Left for other lanes: `GOPORT_LOAD_DUMP`, `GOPORT_LOAD_TIMES` (L1/C2),
`GOPORT_CHECK_VERSION_TABLES`, `GOPORT_FLOWSKIP_STATS`,
`GOPORT_PREFETCH_STATS`, `GOPORT_RESOLVE_AHEAD_STATS`, `GOPORT_TRACE`,
`GOPORT_THP_GUARD_DEBUG` (not in C1's list). `fast_mode.rs` still documents
`GOPORT_LAZY_MEMBERS=0`/`=1` per-part switches (C3).
